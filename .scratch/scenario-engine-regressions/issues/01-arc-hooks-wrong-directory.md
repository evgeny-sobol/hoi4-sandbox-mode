# 01 - Arc hooks are compiled into `common/on_actions/`

Status: ready-for-agent
Type: task
Blocked by: none

## Problem

`6760a43` moved the four per-mod arc hooks out of the on_actions skeleton into a separate
generated file, but the generated file lands in `common/on_actions/`. That directory is parsed
as an on_actions file, so effect definitions are rejected:

```
error.log:7  Error: "Unexpected token: sandbox_arc_on_weekly, near line: 5" in file: "common/on_actions/99_sandbox_arc_hooks.txt" near line: 6
error.log:8  Error: "Unexpected token: sandbox_arc_tick_hosts, near line: 8" in file: "common/on_actions/99_sandbox_arc_hooks.txt" near line: 9
error.log:9  Error: "Unexpected token: sandbox_arc_wargoal_expire_hook, near line: 12" in file: "common/on_actions/99_sandbox_arc_hooks.txt" near line: 277
error.log:10 Error: "Unexpected token: sandbox_arc_justify_hook, near line: 280" in file: "common/on_actions/99_sandbox_arc_hooks.txt" near line: 653
```

The generated file is not even wrapped as an effect:

```
common/on_actions/99_sandbox_arc_hooks.txt
  5: sandbox_arc_on_weekly = {
  6: }
```

Because the definitions never load, the four calls in the shared skeleton resolve to nothing:

```
error.log:11 Invalid effect 'sandbox_arc_on_weekly' in common/on_actions/99_sandbox_on_actions.txt line : 67
error.log:12 Unknown effect-type: sandbox_arc_on_weekly, near line: 67
error.log:17 Invalid effect 'sandbox_arc_tick_hosts' ... line : 280
error.log:21 Invalid effect 'sandbox_arc_wargoal_expire_hook' ... line : 465
error.log:25 Invalid effect 'sandbox_arc_justify_hook' ... line : 556
```

Call sites in `core/common/on_actions/99_sandbox_core_on_actions.hsl`: lines 57
(`on_weekly`), 99 (`on_monthly`), 150 (`on_wargoal_expire`), 165
(`on_justifying_wargoal_pulse`).

## Consequences

- `sc_goal_end` and `sc_justify` produce zero telemetry lines. `sandbox_extract.txt` has 0 of
  each over 54 months, while `sc_pick` fired 3 times. Both hooks existed and logged before
  `6760a43` (36 hits of `sc_goal_end` / `sc_justify` in `6760a43^:common/on_actions/99_sandbox_on_actions.hsl`).
- The weekly fuse retry is dead. `_sandbox-r56` defines
  `sandbox_arc_on_weekly(): sandbox_retry_afg_bop_civil_war_fuse()`, so
  `sandbox_retry_afg_bop_civil_war_fuse` (`core/common/scripted_effects/99_sandbox_scripted_effects.hsl:815`)
  is orphaned. `docs/gdd/Civil Wars.md:165` requires exactly this retry ("check again when the
  range is still active and the cap frees"). The other six retries are called directly from
  `on_weekly` (skeleton lines 51-56) and are unaffected.

## Fix

These are effect definitions, so they belong in `common/scripted_effects/`, not
`common/on_actions/`.

- `core/tools/extract_arc_hooks.py`: change the output path to
  `common/scripted_effects/99_sandbox_arc_hooks.hsl`.
- `core/common/on_actions/99_sandbox_core_on_actions.hsl`: update the header comment that
  names the generated file.
- Both mods: delete the stale `common/on_actions/99_sandbox_arc_hooks.txt`, regenerate
  `common/scripted_effects/99_sandbox_arc_hooks.hsl` (per-mod, generated by the tool, never
  overwritten by `sync_core.py`), and update the file list in `.cursor/rules/sync-core-first.mdc`.
- `.include` files and the compiler pick up `.hsl` recursively, so no path list needs editing
  beyond the rule text.

Alternative considered and rejected: keep the file in `common/on_actions/` and wrap the
definitions in a synthetic `on_action`. That would leave effect definitions in a directory
whose only legal content is on_action blocks, and it does not match how the file is generated
or how the skeleton calls it.

## Acceptance

- Compile both mods; no `99_sandbox_arc_hooks` file remains under `common/on_actions/`.
- Re-run a session: `error.log` has zero lines mentioning `99_sandbox_arc_hooks` and zero
  `Invalid effect 'sandbox_arc_*'`.
- With a scenario selected, `sandbox_extract.txt` gains `sc_goal_end` and/or `sc_justify` lines.
- `_sandbox-r56`: `sandbox_retry_afg_bop_civil_war_fuse` is reachable from `on_weekly` again.
