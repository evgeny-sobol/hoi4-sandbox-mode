# 13 - Goal telemetry is blind to event-driven ultimatums

Status: ready-for-agent
Type: bug
Blocked by: none

## Maintainer decision (2026-09-27)

Option 1: use the `sc_crisis` ultimatum lines as the proof of pressure on the event path. No new `sc_goal` probe.

## Problem

`sc_goal` and `sc_justify` sample the wargoal path: `has_wargoal_against(TARGET)` in the monthly
s7 telemetry, and the justify pulse hook for `sc_justify`. But the historical arcs do not use
wargoals. Their war focuses send a `country_event` ultimatum instead, and the war follows from the
event options.

Evidence from the third `_sandbox` session (942 lines, 1936.1 - 1942.6), where the `axis` arc
ignited successfully:

```
1939.4  GER sc_focus GER_reassert_eastern_claims  sc=1 phase=2
1939.6  GER sc_focus GER_demand_sudetenland       sc=1 phase=2
1939.8  GER sc_focus GER_danzig_or_war            sc=1 phase=2
1939.8  GER sc_ignite axis_war + sc_success + sc_end
```

`sc_goal` = 0, `sc_justify` = 0, `sc_goal_end` = 0 for the whole session, while the arc went from
peak to ignition through the event path.

The focus that does the work carries no wargoal:

- `GER_danzig_or_war`: `will_lead_to_war_with = POL`, then a `completion_reward` that sends
  `POL = { country_event = { id = germany.86 } }`. No `create_wargoal`.
- `GER_demand_sudetenland`: same shape, `will_lead_to_war_with` plus an event.
- `GER_war_with_france` is the exception: it does call `create_wargoal` twice.

`germany.86` offers the target two options; the war follows from whichever it picks (the AI takes
the war option most of the time).

## Why it matters

The acceptance checklist reads `sc_goal` / `sc_justify` / `sc_goal_end` as the proof that the arc
is pressing its targets. On every arc that wars through an ultimatum event, those lines are silent
even when the arc is working perfectly, so the telemetry cannot distinguish "the arc is applying
pressure" from "the arc is inert". This is what made issue 08 look like an AI failure.

## Open question

What should the goal telemetry sample so it covers both paths? Candidates:

1. Sample the arc's own pressure instead of the wargoal: the `sc_crisis` ultimatum events already
   log which option the target picked, so a per-target "ultimatum issued / submitted / defied"
   rollup may be enough.
2. Keep `sc_goal` as the wargoal probe and add a second probe for the event path (e.g. a flag set
   by the ultimatum event, sampled monthly).
3. Treat this as documentation only: state in the GDD that `sc_goal` covers the wargoal path and
   the `sc_crisis` lines cover the ultimatum path.

Needs a maintainer decision before an agent picks it up.

## Agent Brief

**Category:** bug
**Summary:** Make the event-ultimatum path readable from `sc_crisis` so an arc that ignites without wargoals does not look inert

**Current behavior:**
The goal probe reports held wargoals only, so an aggressor that presses its declared targets through ultimatum events shows zero goal lines for the whole session even when it reaches ignition. The ultimatum events already log submit/defy outcomes per target, but there is no documented rule saying which line proves pressure on which path.

**Desired behavior:**
After this change, an analyst can tell "the arc applied pressure" from "the arc was inert" without opening the focus files:
- The Scenarios GDD states the coverage rule: the goal probe covers the wargoal path, the crisis lines cover the ultimatum path.
- Every ultimatum on the covered arcs logs a complete per-target outcome (issued or fired, plus submitted/defied), so a session that wars through events leaves a readable trail.
- The acceptance checklist reads the crisis lines for event-path arcs instead of expecting goal lines there.

**Key interfaces:**
- The s7 goal probe behavior: unchanged, still reports held wargoals only.
- The ultimatum event outcomes per arc target: each must leave one traceable crisis line for the fired ultimatum and one for the target decision.
- The Scenarios GDD "Hooks and telemetry" section: documents which probe covers which path.
- The scenario acceptance checklist: references the crisis lines as pressure proof for event-path arcs.

**Acceptance criteria:**
- [ ] A session where the aggressor ignites through ultimatum events shows per-target crisis lines covering the pressure, with zero goal lines accepted as normal for that path.
- [ ] A session where the aggressor holds wargoals still shows goal lines as before.
- [ ] The GDD states that the goal probe is wargoal-only and names which crisis labels cover the ultimatum path.
- [ ] Both mods recompile clean with no new error log lines from scenario files.

**Out of scope:**
- Changing what the goal probe samples; that is issue 16.
- Changing the sampling cadence of the diagnostic package; that is issue 15.
- Changing tag-drift handling; that is issue 14.
- Adding new diagnostic line types.
