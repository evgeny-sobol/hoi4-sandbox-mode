## Long-term Knowledge

### Architecture

<!-- lore:01a18d0a-db1e-7fc0-8ef1-20d133765e4c -->
* **$ai\_sandbox\_modifier() is factor(0)+add(40): a flat baseline, not a kill switch**: \`$ai\_sandbox\_modifier()\` compiles to one modifier block - \`factor = 0\`, \`add = 40\`, \`is\_sandbox\_mode\_on()\` - so in sandbox mode vanilla's own \`ai\_will\_do\` factor is zeroed and replaced by a flat 40 that other sandbox modifiers then scale (\`$crossroad\_modifier(2)\` halves it to 20). Consequence: an UNGATED focus keeps its vanilla weight, which is why the 1.19.4 Afghan branches (factor 10) dominated the AI while the two Spanish reforms, the Ottoman Aceh expedition and the Alupuram works (default 1) were in practice never taken. A missing sandbox include is therefore a real gameplay bug with two opposite symptoms, an over-weighted branch or a dead one, not a cosmetic gap. Keep \`factor\` and \`add\` in the SAME modifier block; splitting them changes the arithmetic.

<!-- lore:01a1b7d8-1233-77bb-9408-0ddfc64851fe -->
* **99\_sandbox\_on\_actions.hsl is generated and in sync\_core.py EXCLUDE - edit neither core alone**: \`common/on\_actions/99\_sandbox\_on\_actions.hsl\` is GENERATED, never copied. The core skeleton lives only in \`common/on\_actions/99\_sandbox\_core\_on\_actions.hsl\` (an \`EXPECTED\_ONLY\_CORE\` file); \`tools/extract\_arc\_hooks.py\` builds each mod's file from that skeleton plus the mod's scenario catalog, so \`sync\_core.py\` calls it "generated ... do not hand-edit" and lists it in \`EXCLUDE\` ("never overwritten by the sync") together with \`99\_sandbox\_scenarios.hsl\`, \`99\_sandbox\_scenario\_triggers.hsl\`, \`99\_sandbox\_scenario\_rules.hsl\`, \`99\_sandbox\_arc\_hooks.hsl\`, \`99\_sandbox\_opinion\_modifiers.hsl\`, \`99\_sandbox\_scorer.hsl\`, plus \`EXCLUDED\_TREES = ("docs/scenarios/",)\`. Trap: a gate or comment changed in core alone reaches no mod - the run reads clean and the flag never fires. Fix: change the core skeleton AND the same line by hand in both generated mod files, then grep each.

<!-- lore:01a18cdf-5c0b-7be7-b8f9-6bc5ed0376c2 -->
* **HoI4 sandbox mods are an overlay: tracked .include/.hsl, generated .txt are gitignored**: Only \`.include\`/\`.hsl\`/\`.hml\` sources are tracked (336); every mod \`.txt\` is a compile output spliced into the CURRENT vanilla text, and all are gitignored (tracked \`.txt\` = 0). Chose this over shipping full-file copies because a copied vanilla file silently shadows vanilla fixes after a patch. Cost: a game patch is a regeneration event, not an adaptation event, and a release packed without recompiling ships stale vanilla. Scope notes: no \`common/defines\`, \`interface/\`, \`keybinds/\`, \`history/\` and no \`common/ideas\` includes, so vanilla idea \`ai\_will\_do\` is never gated (\`disable\_ai\_for\_ideas.py\` output is unused) and \`common/ai\_strategy/\*.txt\` is not overridden - only the additive rivals system is shipped.

<!-- lore:01a174b4-5f3b-77b9-8eec-0b35fbcf4b4d -->
* **One writer per axis: $add\_honor, $add\_tyranny, $add\_rivalry clamp+log+tooltip**: Honor, Tyranny and rivalry each have exactly one writer macro that clamps the value, swaps the band trait through update\_country\_leader\_traits(), emits the #sandbox log line and carries the change tooltip - $add\_honor, $add\_tyranny, $add\_rivalry(slot, value) (this one also fires the detente clear at 0). Writing \&honor, \&tyranny or \&rivalry\[i] directly is forbidden outside initialisation and the leader-change / ruler-change paths. Chose this over scattered writes because a missed clamp or trait swap fails silently, and because tooltip, log triple and stored number then match by construction. Corollary: a by-tag helper such as \`add\_rivalry\_vs()\` must reach \`$add\_rivalry\` exactly once per tag - calling it per matching slot double-charges the value and re-applies the opinion modifier, which lives inside \`$add\_rivalry\` and not in the caller.

### Gotcha

<!-- lore:01a174b4-5f17-749d-8a3d-00f59b8bc33c -->
* **.include deltas are append-only AND, so a vanilla condition inside OR cannot be replaced**: The include splice can only append conditions (AND) to an existing block. Trap: 'Authoritarian may seize power without the party-popularity > 0.5 requirement' looks implementable through available/\`+available:\`, but that gate sits inside a vanilla OR and cannot be removed; \`+available:\` only creates a block when none exists, it never replaces one. Consequence: the Authoritarian gate stays deferred and is expressed only as an AI weight tilt (is\_authoritarian\_leader trigger and tooltips exist and are ready). Do not re-propose \`+available:\` as the fix.

<!-- lore:01a174b4-5f13-7cc8-b57c-a9aaf0de0903 -->
* **$ai\_sandbox\_modifier: factor(0) and add(40) must share one modifier block**: $ai\_sandbox\_modifier must be ONE modifier block carrying factor(0), add(N) and is\_sandbox\_mode\_on(): HOI4 multiplies every \`factor\` into the final focus weight, so a standalone factor(0) block zeroes the focus even when add(40) fires later (AI never takes it, no error/log). \`base\` is valid at \`ai\_will\_do\` top level but INVALID inside \`modifier = {}\` (only factor/add + triggers) - a \`+modifier:\` carrying base(1.0) writes an error.log entry and gates nothing. Appending is safe: inside vanilla \`ai\_will\_do = { factor = 10 }\` the macro yields 10\*0+40 = 40, so it does not zero an existing weight (6,973 navigated blocks). Same pattern for $ai\_sandbox\_set(N) and gated roots (factor(0)+add(N) under has\_completed\_focus trigger, separate factor(0) only in the NOT case). Corollary: aiview shows 0 even on a correct focus because the displayed value includes later add.

* **$crossroad\_modifier(N) is not derivable; N = concurrent options; gate list; opt-in only**: \`$crossroad\_modifier(N)\` is not mechanically derivable: N is how many options are actually available at once, not the size of the \`mutually\_exclusive\` list. Drop it for every member of a group when ANY sibling carries \`FOCUS\_FILTER\_POLITICAL\`/\`\_POLITICAL\_CHARACTER\`, when the fork is already partitioned by party-popularity (\`mtth:\*\_factor\`) or Tyranny, gated by a \`> 0.5\` popularity \`available\` check, or by conflicting \`has\_government\` checks. \`search\_filters\` are not prerequisites (AFG\_turanist\_abitions vs AFG\_heirs\_of\_the\_chagatai are WAR\_SUPPORT-only and still get crossroad(2)). Of 455 groups passing those gates, 79 deliberately lack one while ~20 political ones carry it, so never auto-emit: opt-in \`--crossroad\` prints candidates for human paste, and never drop an existing one. Compiled, crossroad halves weight via \`set\_temp\_variable f = 1/N\` / \`factor = f\`, no add. By contrast \`$root\_modifier()\` on focus\_tree roots is 99.95% exact (342/342 roots; only 13 tree non-roots and 2 top non-roots are hand exceptions).
