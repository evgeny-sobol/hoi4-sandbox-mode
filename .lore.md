## Long-term Knowledge

### Architecture

<!-- lore:01a18d0a-db1e-7fc0-8ef1-20d133765e4c -->
* **$ai\_sandbox\_modifier() is factor(0)+add(40): a flat baseline, not a kill switch**: \`$ai\_sandbox\_modifier()\` compiles to one modifier block - \`factor = 0\`, \`add = 40\`, \`is\_sandbox\_mode\_on()\` - so in sandbox mode vanilla's own \`ai\_will\_do\` factor is zeroed and replaced by a flat 40 that other sandbox modifiers then scale (\`$crossroad\_modifier(2)\` halves it to 20). Consequence: an UNGATED focus keeps its vanilla weight, which is why the 1.19.4 Afghan branches (factor 10) dominated the AI while the two Spanish reforms, the Ottoman Aceh expedition and the Alupuram works (default 1) were in practice never taken. A missing sandbox include is therefore a real gameplay bug with two opposite symptoms, an over-weighted branch or a dead one, not a cosmetic gap. Keep \`factor\` and \`add\` in the SAME modifier block; splitting them changes the arithmetic.

<!-- lore:01a18cdf-5c0b-7be7-b8f9-6bc5ed0376c2 -->
* **HoI4 sandbox mods are an overlay: tracked .include/.hsl, generated .txt are gitignored**: Only \`.include\`/\`.hsl\`/\`.hml\` sources are tracked (336); every mod \`.txt\` is a compile output spliced into the CURRENT vanilla text, and all are gitignored (tracked \`.txt\` = 0). Chose this over shipping full-file copies because a copied vanilla file silently shadows vanilla fixes after a patch. Cost: a game patch is a regeneration event, not an adaptation event, and a release packed without recompiling ships stale vanilla. Scope notes: no \`common/defines\`, \`interface/\`, \`keybinds/\`, \`history/\` and no \`common/ideas\` includes, so vanilla idea \`ai\_will\_do\` is never gated (\`disable\_ai\_for\_ideas.py\` output is unused) and \`common/ai\_strategy/\*.txt\` is not overridden - only the additive rivals system is shipped.

<!-- lore:01a174b4-5f3b-77b9-8eec-0b35fbcf4b4d -->
* **One writer per axis: $add\_honor, $add\_tyranny, $add\_rivalry clamp+log+tooltip**: Honor, Tyranny and rivalry each have exactly one writer macro that clamps the value, swaps the band trait through update\_country\_leader\_traits(), emits the #sandbox log line and carries the change tooltip - $add\_honor, $add\_tyranny, $add\_rivalry(slot, value) (this one also fires the detente clear at 0). Writing \&honor, \&tyranny or \&rivalry\[i] directly is forbidden outside initialisation and the leader-change / ruler-change paths. Chose this over scattered writes because a missed clamp or trait swap fails silently, and because tooltip, log triple and stored number then match by construction. Corollary: a by-tag helper such as \`add\_rivalry\_vs()\` must reach \`$add\_rivalry\` exactly once per tag - calling it per matching slot double-charges the value and re-applies the opinion modifier, which lives inside \`$add\_rivalry\` and not in the caller.

<!-- lore:01a1a87f-1cb5-73e3-be4d-b941b0c5c632 -->
* **Sandbox scenario director phases, 12-month peak\_timeout, phase<3 telemetry gating**: \`global.sandbox\_scenario\_phase\`: 0 smolder, 1 crises, 2 peak, 3 ended; \`sandbox\_scenario\_arc\_months\` increments only while phase<3. The tick runs monthly in ONE host - HAI primary, else GER -> SOV -> JAP -> ITA -> ENG -> USA -> per-mod \`sandbox\_arc\_tick\_hosts\` (vanilla pass, Rt56 FRA-then-HUN). Peak ends on the 12-month \`$sandbox\_check\_peak\_timeout()\` derail; a civil-war derail fires after 12 months of the aggressor at civil war. Every per-arc tick, \`sandbox\_scenario\_s7\_telemetry\` and every derail arm is gated \`phase < 3\`, so a stuck phase 3 means total director silence while the game plays on - not a missing log flag. Scenario 7 (USA) is repick-eligible but has no \`gen\_\*\` tick/derail/telemetry functions.

<!-- lore:01a1b225-9dc6-7827-b65f-772fe6889853 -->
* **sandbox\_check\_peak\_timeout runs in the HAI host scope; core cannot scope into the aggressor**: \`sandbox\_check\_peak\_timeout()\` (core \`common/macros.hml\`) is called from \`sandbox\_scenario\_check\_derail()\`, so it runs in the monthly tick host's scope (HAI), not the aggressor's - proven by \`\[THIS.GetTag]\` printing \`HAI\` and by the compiled log. Fix = delegation: core calls the mod-defined hook \`sandbox\_log\_peak\_timeout\_detail()\`, mirroring the existing contract \`sandbox\_log\_scenario\_success()\` (core \`99\_sandbox\_engine.hsl\` sites 46/57/63). Chose delegation over moving the catalog into core because core ships no scenario catalog.

<!-- lore:01a1b62a-e610-7631-aced-4c4fb3bb558c -->
* **sandbox\_seed\_rival replaces the weakest slot itself, bypassing set\_rival's dup guard**: \`sandbox\_seed\_rival(\_tag\_, \_intensity\_)\` handles an already-listed tag on its own: it takes \`rivalry\_vs\` = max over the slots holding \`\_tag\_\` and, when that is below \`\_intensity\_\`, writes only the delta. Policy: an empty national slot wins, else the lowest slot is replaced (scenario priority), and the displaced rival gets the usual 24-month cooldown from \`clear\_rival\`. Consequence: a scenario seed is never silently dropped by \`set\_rival()\`'s duplicate backstop - do not 'fix' that as a bug. Invariant at the head of the effect: literal tags appear only as scope heads and comparisons; \`rival\_tag\` always takes a scope (PREV), never a literal, so no tag value enters a variable. No scenario code calls it yet.

### Gotcha

<!-- lore:01a174b4-5f17-749d-8a3d-00f59b8bc33c -->
* **.include deltas are append-only AND, so a vanilla condition inside OR cannot be replaced**: The include splice can only append conditions (AND) to an existing block. Trap: 'Authoritarian may seize power without the party-popularity > 0.5 requirement' looks implementable through available/\`+available:\`, but that gate sits inside a vanilla OR and cannot be removed; \`+available:\` only creates a block when none exists, it never replaces one. Consequence: the Authoritarian gate stays deferred and is expressed only as an AI weight tilt (is\_authoritarian\_leader trigger and tooltips exist and are ready). Do not re-propose \`+available:\` as the fix.

<!-- lore:01a1b158-b174-775d-b910-f7b8c1c386ab -->
* **.lore.md is rewritten by the background lore process after the commit - amend again**: Trap: the squash looks finished the moment \`git commit --amend\` returns, but the background lore process may write new entries into \`.lore.md\` a minute later (once +9 lines / 3 entries; another +12/-3 after the amend itself, folded in with a second amend that moved \`\_sandbox\` HEAD c15773a -> ac61a25). The rewrite is NOT guaranteed - on 2026-11-06 19:56 the file did not move at all. Fix: re-run \`git status\` right before reporting and, only if the file moved, \`git add .lore.md\` and amend the SAME commit again - never add a second commit - then say in the report that it had to be folded in. Never report a clean tree while \`.lore.md\` is still modified or untracked.

* **\* text=auto eol=lf does not normalize CRLF in these repos' staged blobs (core.autocrlf=true)**: Trap: after \`chore(git): force LF line endings for text files\` the repos carry \`\* text=auto eol=lf\`, so CR bytes inside a staged \`.md\` blob look like a defect to fix before committing. They are not: \`core.autocrlf=true\` is set, \`core.eol\` unset, and history already holds CR (AGENTS.md 14, \`docs/gdd/Scenarios.md\` 440, ADR-0008 85); staged counts of new files equal their worktree counts. The mirror image is the generated \`docs/gdd/Scenarios Catalog.md\`: it shows \`M\` in both mods with content identical, git warns 'CRLF will be replaced by LF the next time Git touches it', \`git add\` collapses it to an EMPTY staged diff, and the file simply stays in the status list - the commit carries zero bytes. Fix: compare against an already-committed blob of the same kind; never re-normalize as pre-commit hygiene.

* **$ai\_sandbox\_modifier: factor(0) and add(40) must share one modifier block**: $ai\_sandbox\_modifier must be ONE modifier block carrying factor(0), add(N) and is\_sandbox\_mode\_on(): HOI4 multiplies every \`factor\` into the final focus weight, so a standalone factor(0) block zeroes the focus even when add(40) fires later (AI never takes it, no error/log). \`base\` is valid at \`ai\_will\_do\` top level but INVALID inside \`modifier = {}\` (only factor/add + triggers) - a \`+modifier:\` carrying base(1.0) writes an error.log entry and gates nothing. Appending is safe: inside vanilla \`ai\_will\_do = { factor = 10 }\` the macro yields 10\*0+40 = 40, so it does not zero an existing weight (6,973 navigated blocks). Same pattern for $ai\_sandbox\_set(N) and gated roots (factor(0)+add(N) under has\_completed\_focus trigger, separate factor(0) only in the NOT case). Corollary: aiview shows 0 even on a correct focus because the displayed value includes later add.

<!-- lore:01a18ce5-0d55-7cd6-b5f6-95df388eacb4 -->
* **$crossroad\_modifier(N) is not derivable; N = concurrent options; gate list; opt-in only**: \`$crossroad\_modifier(N)\` is not mechanically derivable: N is how many options are actually available at once, not the size of the \`mutually\_exclusive\` list. Drop it for every member of a group when ANY sibling carries \`FOCUS\_FILTER\_POLITICAL\`/\`\_POLITICAL\_CHARACTER\`, when the fork is already partitioned by party-popularity (\`mtth:\*\_factor\`) or Tyranny, gated by a \`> 0.5\` popularity \`available\` check, or by conflicting \`has\_government\` checks. \`search\_filters\` are not prerequisites (AFG\_turanist\_abitions vs AFG\_heirs\_of\_the\_chagatai are WAR\_SUPPORT-only and still get crossroad(2)). Compiled, crossroad halves weight via \`set\_temp\_variable f = 1/N\` / \`factor = f\`, no add. By contrast \`$root\_modifier()\` on focus\_tree roots is 99.95% exact (342/342 roots; only 13 tree non-roots and 2 top non-roots are hand exceptions).
